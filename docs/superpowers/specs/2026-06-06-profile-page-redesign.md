# Спецификация: Редизайн страницы профиля

**Дата:** 2026-06-06  
**Файл:** `app/profile/page.tsx`

---

## Цель

Сделать страницу профиля информативной и вовлекающей: участник видит своё место, динамику, аналитику по прогнозам и сравнение с другими — всё на одной странице.

---

## Структура страницы (сверху вниз)

### 1. Шапка

Аватар-кружок с инициалами (цвет — жёлтый), имя, email, бейдж `#N место` справа.

### 2. Четыре плашки (сетка 2×2)

| Плашка | Значение | Цвет |
|--------|----------|------|
| Очков всего | сумма points | жёлтый |
| Точность угаданий | `угадано / сыгранные * 100%` | зелёный |
| Серия подряд 🔥 | N последних матчей подряд с points > 0 | оранжевый |
| Прогнозов | `X / 48` + прогресс-бар | белый |

«Угадано» = матчи, где points > 0 (точный счёт или правильный исход).  
Серия: считается с конца списка завершённых матчей, сбрасывается при первом +0.

### 3. Мини-рейтинг

Показывает участника выше (#N-1), текущего пользователя (подсвечен), участника ниже (#N+1).  
Для каждого: место, имя, очки, горизонтальный bar (ширина пропорциональна очкам лидера).  
Строка «До #N места: X очков» под списком.  
Если пользователь #1 — не показывать строку «До ... места».

### 4. График очков по этапам

Столбчатый барчарт. Этапы по оси X: Тур 1 / Тур 2 / Тур 3 / 1/8 / 1/4 / 1/2 / Финал.  
Тур 1/2/3 — матчи стадии GROUP, разбитые по порядку внутри каждой группы.  
Этапы без сыгранных матчей отображаются серым (высота минимальная).

### 5. Аналитика (сетка 2×2)

#### 5а. 100% попаданий
Число точных прогнозов (points = 11, 22 или 32) из числа завершённых.  
Прогресс-бар: `exactCount / finishedCount`.

#### 5б. Динамика очков
Мини-барчарт: очки за каждый этап (Тур 1, Тур 2, Тур 3, 1/8 ...).  
Подписи под каждым столбцом — название этапа и очки числом.  
Лучший этап выделен ярче.

#### 5в. Сравнение с группой
Три строки:
- **Угадал только ты** — N матчей, где твой точный счёт не угадал никто другой
- **Все угадали, кроме тебя** — N завершённых матчей с points=0, где у остальных points > 0
- **Самый редкий прогноз** — матч, где точный счёт угадали наименьшее число людей (и ты в их числе)

Если таких матчей нет — строки скрыты.

#### 5г. Двойник
Другой участник с наибольшим числом совпадающих прогнозов (одинаковый homeScore + awayScore на один и тот же матч).  
Показывает: аватар-инициал, имя, место в рейтинге, «Совпадают N из M прогнозов».  
Если менее 3 прогнозов сдано — блок не показывать.

### 6. Список прогнозов

Заголовок «Мои прогнозы». Хронологический порядок (kickoff asc).

**Карточка — завершённый матч:**
```
[цветная полоска слева] Флаг Команда А — Флаг Команда Б    [бейдж очков]
                        Дата · Группа/Этап
───────────────────────────────────────────────────────
Мой прогноз             Итог матча
2 : 1                   2 : 1  ✓
```

Цвет левой полоски и бейджа:
- **Зелёный** — точный счёт (points = 11/22/32)
- **Жёлтый** — исход угадан (points = 7/14)
- **Серый** — промах (points = 0)

Итог матча окрашен в цвет результата (зелёный/жёлтый/серый).

**Карточка — ожидаемый матч** (пунктирная рамка, без цветной полоски):
```
[пунктирная рамка] Флаг Команда А — Флаг Команда Б    [ожидается]
                   Дата · Группа/Этап
───────────────────────────────────────────────────────
Мой прогноз
2 : 1
```

## Данные

Все данные загружаются серверным компонентом (`async` Server Component).

### Запросы к БД

1. **Прогнозы пользователя** — `prediction.findMany` с `include: { match: true }`, `orderBy: kickoff asc`
2. **Все пользователи для рейтинга** — `user.findMany` с `select: { id, name, predictions: { points } }` (без isAdmin) — для вычисления места и мини-рейтинга
3. **Прогнозы всех пользователей на одни матчи** — нужны для блоков «Сравнение» и «Двойник»: `prediction.findMany({ where: { matchId: { in: userMatchIds } }, select: { userId, matchId, homeScore, awayScore, points } })`

### Вычисления (helper-функции в `lib/profile-stats.ts`)

- `calcRank(userId, allUsers)` → `{ rank, total, above, below }`
- `calcStreak(predictions)` → число последних подряд с points > 0
- `calcPointsByStage(predictions)` → `Record<stage, number>`
- `calcTwin(userId, allPredictions)` → `{ userId, name, matchCount }` | null
- `calcComparison(userId, allPredictions)` → `{ uniquelyCorrect, missedByOnly, rarestMatch }`

## Что не меняется

- Авторизация (redirect если нет сессии)
- API-эндпоинты (страница остаётся Server Component, запросы к БД напрямую)
- Схема БД (новые поля не нужны)

---

## Ограничения

- Блок «Двойник» не показывается если у пользователя < 3 прогнозов
- Блок «Сравнение» не показывается если нет завершённых матчей
- Блок «Серия» показывает 0 если ни один матч не завершён
- Аналитика по турам (Тур 1/2/3) использует ту же логику что и в `/matches` — порядок внутри группы, не дата
