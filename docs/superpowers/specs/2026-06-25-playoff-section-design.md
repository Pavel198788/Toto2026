# Раздел Play-off — дизайн

**Дата:** 2026-06-25
**Статус:** утверждён к реализации

## Цель

Добавить полноценную работу с плей-офф ЧМ-2026 в двух местах:
1. Раздел «Плей-офф» как фильтр во вкладке **Матчи**.
2. Отдельная вкладка **ПЛЕЙ-ОФФ** в навигации (перед «Сеткой») со списком матчей, сгруппированным по стадиям.

Заодно закрыть существующий баг: стадия `ROUND_OF_32` (1/16 финала) есть в схеме и в подсчёте очков, но отсутствует в фильтрах вкладки «Матчи», из-за чего такие матчи не попадают ни под один фильтр кроме «Все».

## Контекст

- ЧМ-2026: 48 команд. Плей-офф: 1/16 (ROUND_OF_32, 32 команды) → 1/8 (R16) → 1/4 (QUARTERFINAL) → 1/2 (SEMIFINAL) → за 3-е место (THIRD_PLACE) → финал (FINAL).
- `enum Stage` уже содержит все стадии ([prisma/schema.prisma](../../../prisma/schema.prisma)).
- `calculatePoints` уже считает очки для всех плей-офф стадий ([lib/scoring.ts](../../../lib/scoring.ts)); `ROUND_OF_32` обрабатывается общей плей-офф веткой (25 / 10 / 10).
- «Сетка» (`/grid`) — это таблица прогнозов участников, **не** турнирный bracket.
- Поле `Match.winner` хранит победителя матча (учитывает серию пенальти) — используется для подсветки «прошёл дальше».

## Решения (зафиксированы в брейншторме)

- Отдельная вкладка Play-off = **список матчей по стадиям** (не bracket-дерево).
- Во вкладке «Матчи» = **добавить** чип «Плей-офф» рядом с отдельными стадиями + починить 1/16 (ничего не убираем).
- Строка матча = как в «Матчах» **+ подсветка победителя и стрелка «прошёл дальше»** для завершённых плей-офф матчей.

## Часть 1 — Вкладка «Матчи» (фильтры)

**Файлы:** [app/matches/page.tsx](../../../app/matches/page.tsx), [components/matches-tabs.tsx](../../../components/matches-tabs.tsx)

- В массив `TABS` добавить:
  - `{ key: "playoff", label: "Плей-офф" }` — сводный фильтр всех плей-офф матчей.
  - `{ key: "ROUND_OF_32", label: "1/16 финала" }` — починка пропавшей стадии.
- Итоговый порядок чипов:
  `Все · Тур 1 · Тур 2 · Тур 3 · Плей-офф · 1/16 · 1/8 · 1/4 · 1/2 · За 3-е · Финал`
- Логика фильтрации в `app/matches/page.tsx`:
  - Добавить набор плей-офф стадий: `PLAYOFF_STAGES = {ROUND_OF_32, R16, QUARTERFINAL, SEMIFINAL, THIRD_PLACE, FINAL}`.
  - При `tab === "playoff"` → показывать матчи, где `m.stage` входит в `PLAYOFF_STAGES`.
  - Существующая логика `getMatchTab` для отдельных стадий не меняется (она уже возвращает `m.stage` для не-GROUP).
- Счётчики чипов:
  - `counts["playoff"]` = число матчей со стадией из `PLAYOFF_STAGES`.
  - `counts["ROUND_OF_32"]` уже посчитается существующим циклом (через `getMatchTab`).
- Список матчей внутри фильтра «Плей-офф» остаётся сгруппирован **по датам** (хронологически) — текущее поведение, без изменений группировки.
- Фильтр видимости чипов (`t.count > 0`) сохраняется: «Плей-офф» и «1/16» появятся, когда такие матчи будут в БД.

## Часть 2 — Новая вкладка «ПЛЕЙ-ОФФ»

**Файлы:** [components/nav-tabs.tsx](../../../components/nav-tabs.tsx), новый `app/playoff/page.tsx`

- В `nav-tabs.tsx` вставить `{ href: "/playoff", label: "ПЛЕЙ-ОФФ" }` между `ПРОФИЛЬ` и `СЕТКА`:
  `МАТЧИ · РЕЙТИНГ · АНАЛИТИКА · ПРОФИЛЬ · ПЛЕЙ-ОФФ · СЕТКА · ГРУППЫ · БОНУС · ПРАВИЛА`
- Новый роут `app/playoff/page.tsx` (`force-dynamic`):
  - Доступ публичный, как у `/matches` (без редиректа на логин). «Моя ставка»/очки подтягиваются только при наличии сессии.
  - Запрос: все матчи со стадией из `PLAYOFF_STAGES`, упорядочить по `kickoff asc`.
  - Группировка **по стадиям** в порядке: ROUND_OF_32 → R16 → QUARTERFINAL → SEMIFINAL → THIRD_PLACE → FINAL. Заголовок секции = русский лейбл стадии («1/16 финала», «1/8 финала», …).
  - Секция стадии рендерится только если в ней есть хотя бы один матч (пустые будущие стадии не показываются). Если плей-офф матчей нет вовсе — пустое состояние («Плей-офф ещё не начался»).
  - Серилизация матчей и прогнозов — как в `/matches` (переиспользовать тип `SerializedMatch`/`SerializedPrediction`).

## Часть 3 — Строка матча с подсветкой «прошёл дальше»

**Файл:** [components/matches-list.tsx](../../../components/matches-list.tsx)

- `MatchesList` уже принимает `byDate: DateGroup[]` (`{dateKey, label, matches}`). Для вкладки Play-off передаём группы, где `label` = название стадии. Компонент переиспользуется как есть для группировки.
- Добавить опциональный проп `showAdvance?: boolean`:
  - Когда `showAdvance` и матч `FINISHED` и задан `match.winner` — подсветить команду-победителя (сравнение названия `winner` с `homeTeam`/`awayTeam`) жёлтым и показать стрелку **↑**. Если `winner` пуст — подсветки нет (никаких догадок по счёту).
  - В обычной вкладке «Матчи» проп не передаётся → поведение не меняется.
- Определение победителя: предпочесть поле `Match.winner` (название команды). `SerializedMatch` уже не содержит `winner` — **добавить поле `winner: string | null`** в `SerializedMatch` и в серилизацию на обеих страницах (`/matches`, `/playoff`).

## Что НЕ трогаем

- `lib/scoring.ts` — очки за плей-офф уже корректны (off-limits).
- `prisma/schema.prisma` — все стадии уже есть (off-limits).
- Изменение порядка навигации выполняется по явному запросу пользователя (добавить вкладку Play-off перед «Сеткой»).

## Критерии готовности

- Во вкладке «Матчи» есть чипы «Плей-офф» и «1/16», фильтры работают, счётчики верны.
- Вкладка «ПЛЕЙ-ОФФ» доступна из навигации (перед «Сеткой»), показывает матчи по стадиям, у завершённых — подсветка победителя и стрелка.
- Незалогиненный видит матчи без «моей ставки»; залогиненный — со ставкой и очками.
- `npm run build` проходит без ошибок.
